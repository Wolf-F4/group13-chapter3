# 第一次 Git 实验总结

## 1. git add 的作用
将工作区（Working Directory）中文件的修改（包括新增、修改或删除）添加到暂存区（Staging Area）。这是提交前的重要一步，允许用户有选择地分批保存修改。

## 2. git commit 的作用
将暂存区（Staging Area）的内容提交到本地仓库（Local Repository）。每次提交都会生成一个唯一的版本记录（Commit ID）和提交信息，作为项目历史的一个快照保存下来。

## 3. git restore notes.md 的作用
撤销工作区中 `notes.md` 文件的修改，将其恢复到上一次提交（或暂存）时的状态。
> **注意**：这是一项具有“破坏性”的操作，执行后工作区中未提交的修改将会永久丢失。

## 4. commit 与 push 的区别
- **commit（提交）**：是将修改保存到**本地仓库**的操作。它完全在本地电脑上执行，不需要网络，是记录版本历史的核心步骤。
- **push（推送）**：是将本地仓库的提交推送到**远程仓库（如 GitHub）**的操作。它需要网络连接，主要用于团队协作和代码云端备份。

## 5. 总结与体会
通过本次实验，我理解了 Git 的核心工作流：**工作区修改 -> git add -> 暂存区 -> git commit -> 本地仓库 -> git push -> 远程仓库(GitHub)**。掌握了这些基本命令，能够很好地管理代码的版本，并为后续团队协作打下了基础。
